# ひより珈琲 デモサイト設計書 — run 1

担当：Codex（設計・チェック）  
実装担当：Antigravity（agy）  
対象：ビルドツールを使わない静的5ページ

## 1. デザイン方針

### コンセプトの解釈

住宅街で、近所の人が日常的に立ち寄る小さな自家焙煎カフェ。華やかさより、読みやすさと落ち着きを優先する。

初めて訪れた人が30秒以内に「メニューと価格」「営業日」「場所」を確認できる構成にする。トップの冒頭に営業時間と主要導線を置き、その直後に今週の営業日を示す。

写真のような大きな面を使って空気感を出すが、素材はCSSで描く架空のイラストのみとする。実在の写真、ロゴ、口コミ、受賞歴は使わない。価格、住所、店主紹介も本設計で創作した設定である。

### デザイントークン

| 用途 | 値 | 使い方 |
|---|---|---|
| 基調色 | `#FAF6EF` | ページ背景 |
| 面の色 | `#FFFDF8` | カード・ヘッダー |
| 本文色 | `#302D28` | 本文・見出し |
| 補助文字色 | `#625B52` | 注記・補足 |
| 深緑 | `#24483E` | 主ボタン・リンク・営業表示 |
| 焙煎ブラウン | `#795039` | アクセント・装飾 |
| 境界線 | `#D8CFC2` | 区切り線・カード枠 |
| 休業表示 | `#8B3F35` | 休業ラベル・エラー |
| フォーカス色 | `#245FA5` | キーボード操作時の輪郭 |

- 本文フォント：`-apple-system, BlinkMacSystemFont, "Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif`。
- 店名と大見出しのみ：`"Yu Mincho", "Hiragino Mincho ProN", serif`。
- 外部フォントは読み込まない。
- 本文16px以上、行高1.8。注記14px以上。大見出しはスマホ32px、広い画面44pxを上限とする。
- 余白単位：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80px。
- 横余白：スマホ20px、768px以上32px。本文全体の最大幅1120px、長文は680px。
- セクション間隔：スマホ48px、768px以上80px。
- 角丸：カード12px、ボタン8px、小ラベル4px。過度な丸みや強い影は使わない。
- タップ領域は最低44×44px。価格の数字は桁幅を揃える。
- 色だけで営業・休業を区別せず、必ず文字を添える。

### 共通レイアウト

**ページ上端**

全ページに次の告知を表示する。

> 架空のカフェのデモサイトです。掲載情報はサンプルです。実際の営業・予約受付は行っていません。

**ヘッダー**

- 左にテキストロゴ「ひより珈琲」。トップへのリンク。
- 768px以上では右に「メニュー」「お店について」「営業日・アクセス」「お問い合わせ・予約」。
- 767px以下では「メニューを開く」ボタンで縦型ナビを開閉する。店の商品ページと混同しないよう、開閉ボタンを単に「メニュー」と表記しない。
- 開閉ボタンに`aria-expanded`と`aria-controls`を付ける。Escapeで閉じ、開閉ボタンへフォーカスを戻す。
- ヘッダーは固定しない。現在ページに`aria-current="page"`を付ける。
- 本文へ移動するスキップリンクを用意する。

**フッター**

次の順に配置する。

1. 店名、短い紹介、営業時間。
2. 全5ページへのリンク。
3. Instagram導線とQRの置き場。
4. 口コミQRの置き場。
5. デモの注記と著作権表記。

掲載文案：

> ひより珈琲  
> 住宅街の片隅で、珈琲とひと休み。  
> 9:00〜17:00／モーニング 9:00〜11:00／火曜定休・臨時休業あり

> Instagram  
> 日々のお知らせを載せる場所です。  
> デモのため、アカウントへのリンクはありません。

> ご感想はこちら  
> レジ横でご案内する口コミQRの設置イメージです。  
> デモのため、口コミの閲覧・投稿はできません。

QRは「QR設置位置」と書いた枠にする。読み取れるQRコードや実在アカウントは使わない。リンク先がない要素をリンクやボタンにしない。

著作権表記：

> © ひより珈琲 — 架空店舗のデモサイト

**スマホ固定下部バー**

- 767px以下で表示。3等分して「電話する」「地図を見る」「メニュー」。
- 「電話する」はお問い合わせページの`#phone`へ移動。実在番号に発信する`tel:`は設置しない。
- 「地図を見る」は営業日・アクセスページの`#access`へ移動。遷移先に「アクセス案内（地図の代わり）」を表示する。
- 「メニュー」はメニューページへ移動。
- 高さ64pxに`env(safe-area-inset-bottom)`を加える。
- 本文下部に同等以上の余白を確保し、フッターや送信結果を隠さない。
- 768px以上では非表示。

固定の対象週を**2026年11月9日（月）〜15日（日）**とする。

|---|---|
| 11/9（月） | 営業 9:00〜17:00 |
| 11/10（火） | 定休日 |
| 11/11（水） | 営業 9:00〜17:00 |
| 11/12（木） | 臨時休業 |
| 11/13（金） | 営業 9:00〜17:00 |
| 11/14（土） | 営業 9:00〜17:00 |
| 11/15（日） | 営業 9:00〜17:00 |

- トップと営業日ページは同じJSデータから表示する。
- 「今週の営業日」の直下に「表示例：2026年11月9日〜15日」と明記する。

- 共通ステータスは「営業日サンプルを表示しています」とする。
- JS無効時は各HTMLに記載した営業時間・定休日と、営業日サンプルが表示できない旨を読めるようにする。

## 5. agyへの実装指示

### レスポンシブ

- モバイルを基本とする。
- 768px未満：1カラム、折りたたみナビ、固定下部バー。
- 768px以上：通常ナビ、ヒーロー2カラム、紹介カード3カラム。
- 1024px以上：カラム間隔を48pxに拡張。最大幅1120pxで中央寄せ。
- メニューの商品名・説明・価格は小画面でも対応が明確な配置にする。固定幅を避ける。
- 320px幅で横スクロールを発生させない。トップの週一覧は縦並びにする。

### プレースホルダ

- CSSの図形とグラデーションでカップ、トースト、窓、焙煎機を表現する。
- ヒーローは4:3、メニューの装飾は3:2。レイアウト領域を事前に確保する。
- 淡い生成り、緑、ブラウンで統一し、素材エラーのような空白にしない。
- 各イラストに「イメージイラスト」と小さく表示する。
- 装飾は`aria-hidden="true"`とし、必要な情報は隣の本文に置く。
- 実在店舗の写真、外部画像URL、架空の口コミ、読めるQRは使わない。

### HTML・アクセシビリティ

- `lang="ja"`、viewport、各ページ固有のtitleとdescriptionを設定する。
- titleは「メニュー｜ひより珈琲（架空カフェのデモ）」の形式。
- 1ページ1つのh1。見出し順序を守り、header/nav/main/footerを使用する。
- リンクはリンク、操作はbuttonで実装する。クリック専用のdivを作らない。
- キーボードフォーカスを消さない。本文の通常文字はコントラスト比4.5:1以上を確認する。
- 動きを付ける場合も短い色変化程度とし、`prefers-reduced-motion`に対応する。
- 固定バーに隠れないようアンカー位置に`scroll-margin`を設定する。
- デモサイトには`<meta name="robots" content="noindex, nofollow">`を付ける。

### JSと営業日表示

- 通常の`defer`付きスクリプトを使用し、モジュール読み込みやfetchを必須にしない。
- `business-hours.js`に日付・曜日・区分・営業時間を一元管理する。
- 臨時休業を通常の営業時間より優先して表示する。
- 日付は文字列からそのまま表示し、タイムゾーン変換による日付ずれを避ける。
- 対象期間外も固定サンプルとして表示し続け、現在の営業状況と誤認させない。
- JS無効時もナビと主要情報を利用可能にする。ナビはJSによる初期化後に折りたたむ。

### フォームモック

- 入力欄はすべて明示的なlabelと関連付ける。
- JS初期化前は送信ボタンを無効にする。`noscript`で「送信デモにはJavaScriptが必要です」と表示する。
- JS初期化時にsubmit処理を登録してからボタンを有効にする。
- submitで`preventDefault()`し、HTTP送信はしない。
- `fetch`、メール送信、外部フォーム、分析サービス、Cookie、localStorage、sessionStorageは使用しない。
- 入力値をURLやコンソールへ出力しない。結果表示に入力内容を転載しない。
- 必須、email形式、文字数、空白だけの入力を検証する。
- エラーは項目の近くに表示し、`aria-invalid`と`aria-describedby`を設定する。最初の不正項目へフォーカスを移す。
- 成功結果は`role="status"`で通知し、入力をクリアする。
- 個人情報の同意や予約確定を模した表現は使わない。

- 未確認のこと：検証できなかった環境や残課題。
